# Visual Editing

Codexが編集者として判断し、エンジンがその指定を映像へ反映する。入力とCLIはREADME.mdに従う。

## 映像と音
- 各beatで証拠・比較・因果・具体例・感情・休符のどれが必要か考え、映像を選ぶ。分類を管理項目として毎回書く必要はない。
- 情報や視点が変わる瞬間にカット・強調を置く。固定秒数のカット、常時ズーム、全テロップのSEを機械的に加えない。
- 全文字幕と図の情報量を調整する。図や文字は日本語を基本とし、読む時間を確保する。
- 通常の画像・動画は1920×1080全面を基準にcoverで敷き、見出し・字幕・立ち絵を重ねる。compareとdiagramだけは固定領域を避けた安全領域に置く。
- ずんだもん・めたんの立ち絵は音声に連動する固定動作。Codexは表示・位置・サイズを変更しない。固定領域を避けて図を設計する。
- 素材は案件内へ保存する。動画の尺が足りなければ別素材や別カットへ変更する。同じ素材の再利用は禁止しない。
- 共通のmedia・compare・diagram・focus・textで表現できる場合はデータで指定する。特殊図解だけ案件内のvisuals.tsxを使う。
- 演出は発話開始・終了への参照を優先し、絶対秒数の手直しを減らす。台詞や時間表を図解コードへ写さない。
- BGM、SE、環境音は必要な区間だけ置く。ナレーションを優先し、duckやフェード、無音で重要箇所を目立たせる。素材音量が不適切ならFFmpeg等で音声を正規化してから使う。
- 個人利用では素材の出典・権利・ライセンス台帳を必須にしない。

## 実行とQA
- tools/video.py buildをバックグラウンド起動し、status/waitの短い結果で完了を確認する。ログは失敗調査時だけ読む。
- 音声だけキャッシュし、Remotionで映像と音を含む全体をレンダーする。別の映像合成経路やbeatキャッシュを追加しない。
- inspectで必要なフレームや短い区間を確認し、黒画面、欠損、字幕切れ、読みにくさ、内容不一致、不自然な音や間など確認できた問題を直す。
- 保存する編集用ソースはproject.json、使用素材、必要な特殊図解。標準成果物にASS・OTIO・Kdenliveを加えない。

## サムネイルと納品
- 承認済み方針から既存の画像生成・画像処理ツールでoutput/thumbnail.jpgを作る。独自のサムネイル描画基盤を実装しない。
- 主役を明確にし、少ない文字でタイトルを補う。幅640px以上、16:9のJPEGにし、縮小表示も確認する。
- 完成版は全体デコード検査を通し、tools/video.py deliverでYouTubeへ非公開アップロードする。
- private、処理完了、サムネイルAPI成功を確認する。動画が同じでサムネイルだけ変わった時は再投稿しない。
