# Script

Codexが構成作家として、確認した事実を興味と理解につなげる。

YouTube Shortsの依頼時は [shorts](../shorts/SKILL.md) も読み、短尺構成・縦画面の判断を追加する。短い横動画には適用しない。

## 構成
- タイトル・サムネイルで生じた期待に応える具体的な結果、矛盾、問いから始める。冒頭30秒は目安であり、秒数の合否判定にしない。
- 小さな答えを渡し、その答えから次の疑問へ進む。章の羅列や長い前置きにしない。
- beatは一つの理解のまとまり。複数発話と複数の画面変化を含めてよい。一発話・一カットと同一視しない。
- 一度に説明する因果関係を絞り、何の素材を見せるかを台本と一緒に考える。
- 指定尺は構成量の目安。尺合わせだけの水増し・削減をしない。

## 台本と声
- 音声として自然な短い文を使う。発話本文がそのまま全文字幕になる。
- 声は開始時に決める。未指定はずんだもん。掛け合いの配役未指定ならずんだもんが説明役、めたんが視聴者目線の聞き役。ゆっくり解説の魔理沙と霊夢のように、説明と疑問を受け持つ。
- 聞き役は疑問・反論・自分の言葉での要約で説明を前へ進める。ABABの交互読みや相槌だけの水増しにしない。
- gapは発話後の間。ツッコミ、考える時間、重要な答えの余韻などに応じて指定する。すべて同じ間に揃えない。
- 音声スタイルや読み方の調整は必要な発話だけ指定する。感情分類の必須項目は設けない。

## 保存と承認
- READMEの新形式に従ってproject.jsonへ台本・編集指定・声・タイトル・サムネイル方針・納品設定を保存する。
- 根拠のある数値と事実を使い、調査の出典と留保事項は案件内の短いメモへ残す。発話ごとの主張IDや台帳は必須にしない。
- 承認時は保存済みの台本と主要映像方針を忠実に読みやすく提示する。別の台本を正本として作らない。
- サムネイルは内容に一致する主役と短い補完文言を決め、タイトルと同じ文章を繰り返さない。
